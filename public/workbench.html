How to use ProofPath

ProofPath compares two registered synthetic checkout releases. It does not yet test an arbitrary website or a real customer checkout.

  1. Describe. If Meta testing is enabled, enter your reviewer access code and select Unlock Meta testing. Describe the checkout behavior to check, choose a previous release and a release to test, then generate a test plan. The mode label tells you whether the plan uses Meta or demo data.
  2. Review. Read the proposed checks and coverage gaps. For each requirement, check its interpretation, select whether it is unchanged or new/changed, and make any applicable reference, rule-change or gap decisions. Continue only when the plan reflects what you want tested.
  3. Approve and run. Review the prepared plan, approve it, then select Run approved test. Each approval is valid for one run. Changing the requirement or release pair requires a new review and approval.
  4. See results. Read the candidate and suite verdicts, then open the failed or inconclusive checks and screenshots. PASS means the checks passed; FAIL means at least one check failed; INCONCLUSIVE means the evidence or coverage is insufficient for a complete conclusion. An interrupted run may have incomplete evidence.

Run it again later: save the reviewed regression from the results. Select a release pair and the saved definition under Reuse a saved regression, prepare it, and give fresh approval. Reuse does not generate a new Meta plan.

Privacy and limits: use synthetic requirements only. In Meta mode, generating a plan sends the requirement to Meta and uses the configured proposal budget. Demo mode makes no Meta call. Keep your reviewer access code private.
