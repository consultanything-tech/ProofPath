# ProofPath submission notes

Status: prepared for submission; no submission receipt has been recorded.

## Project

ProofPath helps developers turn checkout acceptance criteria into reviewed browser tests and inspectable regression evidence. Muse Spark 1.3 proposes bounded semantic test cases grounded in registered checkout controls. A person reviews the interpretations, reference policies and coverage gaps, then approves an exact snapshot before Playwright can execute it. An independent typed oracle computes expected results; the model cannot declare PASS or override browser evidence.

The workbench compares a previous and candidate release, links assertions to screenshot hashes and observations, and exports a bug packet or Playwright regression. Reviewed definitions can be reused against a fixed release without another planner call. Candidate PASS and overall suite INCONCLUSIVE remain separate when coverage is incomplete.

Live product: https://proofpath-web-vgrq2gffta-as.a.run.app/workbench.html
Judge access is protected by a reviewer code, prepared for private organizer/judge delivery; it is not included in public materials. Opening saved reports does not spend model allowance.

Built during this hackathon; pre-event work was planning documentation only. The narrated video uses the actual local workbench with explicitly disclosed fixture plans and synthetic data. Separate committed evidence records a real Meta-generated V2 plan, a seeded regression and a saved fixed rerun. GCP hosting, authenticated saved reports and evidence downloads were verified; a new model generation on the hosted service has not been smoke-tested.

## Meta products

The product integrates Meta Model API using muse-spark-1.3 through the Responses API. It grounds a requirement in registered synthetic-checkout capabilities, requests a constrained structured proposal, and validates the result locally before review. Exact input counting and a signed durable admission ledger precede generation. Human-reviewed reference rules feed an independent deterministic oracle; fresh approval is required before bounded browser execution.

One authorized real V2 Meta proposal completed local review, seeded-defect execution and saved fixed-candidate rerun. The candidate passed after the fix while the suite retained INCONCLUSIVE for incomplete coverage. V1 also has a small fixed eight-case live planning evaluation. These are selected integration results, not general reliability claims. The narrated recording explicitly uses fixture plans. The hosted release selects direct Meta; the Baseten prototype is not enabled in that deployment. Development-assistant use is separate from the product's Meta integration.

## Why Meta models matter

Meta's model supplies the language-to-test-plan step: it interprets written requirements and proposes semantic checks within the application's bounded capabilities. This lets a developer inspect an executable interpretation instead of manually translating every requirement into a browser script. ProofPath keeps the model's proposal separate from approval, execution and the verdict, so plausible model text is never treated as proof. The saved reviewed definition can be rerun without another model call; deterministic checks and evidence make the model-assisted workflow inspectable.
